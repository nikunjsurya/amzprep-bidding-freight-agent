Why I Built It This Way

The key decisions I made and the reasoning behind each one
Decision 1
Rate vs. Measurement Confusion
Carriers send numbers in context: "24200 lbs", "rate is 2020", "3 days transit." The AI prompt explicitly distinguishes prices from weights from transit times using surrounding context words. A number next to "rate" is a price. A number next to "lbs" is weight. This prevents the most dangerous parsing error — quoting a customer based on a misread number.
Decision 2
AI at 4 Points, Not Everywhere
The state machine is deterministic — rules-based logic for filtering, timing, markup, tiebreakers. Claude is only called where human language understanding is unavoidable: parsing messy text. This means the system is predictable, testable, and doesn't depend on the LLM for correctness.
Decision 3
Template Fallbacks for Every AI Call
If Claude goes down, the pipeline keeps running with basic templates. A freight quoting system can't stop working because an LLM API has an outage. The fallbacks aren't as good, but the deal still moves forward.
Decision 4
Flag Ambiguity, Don't Guess
When a carrier response is ambiguous ("15,00" — is that $15 or $1500?), the system flags it for manual review rather than guessing. A wrong rate is worse than a delayed rate. Same for attachment references and counter-questions from carriers.
Decision 5
Hard Filter for Carrier Preferences
When FreshBox says "only Amazon Freight," we only contact Amazon Freight. No other carriers. This respects the customer relationship. In production, this could evolve into a weighted preference with a threshold — but for the MVP, we respect the customer's stated preference exactly.
Decision 6
Audit Trail as Production Foundation
Every state change, carrier response, email, and decision is logged with timestamps. This isn't just for debugging — it's the data layer that powers production analytics: carrier reliability scores, win rates, average turnaround, margin tracking. The MVP logging IS the production data pipeline.

How Carriers Get Filtered

Before contacting anyone, the system applies three filters in order
1
Start with all 6 carriers
SmarteFreight, Reach & Freight, Borderless, Consolidated Fastrate, Amazon Freight, XPO Logistics
↓
2
Destination Filter
Is destination an Amazon/FBA warehouse? If NO → remove Amazon Freight (they only service Amazon destinations)
↓
3
Exclusion Filter
Does this customer exclude any carriers? If YES → remove them. Example: TechGear excludes XPO → XPO never contacted for TechGear shipments
↓
4
Preference Filter
Does this customer have preferred carriers? If YES → only contact those. Example: FreshBox prefers Amazon Freight → only Amazon Freight contacted. Safety net: if preferred carrier is ineligible, fall back to all remaining carriers.
↓
✓
Contact surviving carriers only
Every filtering decision is logged in the audit trail. No carrier is contacted unnecessarily. No customer gets a quote from a carrier they don't want.

When Things Go Wrong

I built a response for every failure scenario — the system never crashes, never guesses, never loses data
Layer 1: Claude API Down
Template fallbacks for all 4 AI calls
Messy carriers → flagged for manual review. Quote summary → basic template. Decision explanation → simple statement. Pipeline keeps running.
Layer 2: Orchestrator Step Fails
Try/catch on every pipeline step
If any step throws an unexpected error → state set to ERROR, failure logged in audit trail with details, quote returned in current state. Nothing lost.
Layer 3: Carrier Failures
Timeout, decline, question, attachment
Timeout → skipped, logged. Decline ("no trucks") → marked declined, skipped. Question → flagged for follow-up. Attachment → flagged for manual review. Pipeline continues with whatever we have.
Layer 4: All Carriers Fail
State → LOST
If every carrier times out, declines, or requires manual review → quote is set to LOST with reason "No valid carrier responses received." Customer is notified.
Layer 5: Bad Input
Caught before pipeline starts
Missing fields → 400 error with exact list. Unknown customer → clear error with valid options. Duplicate request → returns existing quote. Empty body → lists all 7 required fields.
Layer 6: Ambiguous Data
Flag it, don't guess
"15,00" — is that $15 or $1,500? Rather than guessing wrong, we flag for manual review. A wrong rate is worse than a delayed rate. Same for rate-per-mile, attachment references, confusing number formats.
Layer 7: Time-Bound Enforcement
Late responses rejected
If a carrier responds after the bidding window closes → their rate is logged but NOT included in evaluation. Audit trail: "Late response from [carrier]. Not included per time-bound rules."
At Scale: 100+ Carriers
Architecture supports it today
